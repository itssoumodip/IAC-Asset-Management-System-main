# Invoice evidence and assisted Finance entry

Admin and Finance can upload an invoice from an asset's Finance record. The original file remains in the private database with its SHA-256, filename, uploader and extraction result. Upload does not change the asset or approve it. Employees, IT support and Executive cannot read these files.

The first version supports text PDFs and plain XLSX up to 4 MiB. Extraction is local, without a third-party extraction API. It uses a bounded worker with a 10-second deadline and two concurrent extractions per API process. PDF limits are 20 pages and 100,000 extracted characters. XLSX limits are 300 archive entries, 20 MiB expanded content, 10 MiB per entry, 10 sheets, 20,000 visited cells and 100,000 extracted characters. Archive entries are checked before workbook parsing; encrypted, macro and external-link workbooks are rejected. Formulas and hyperlinks are not used as field evidence. A file is evidence, never an instruction.

Suggestions use explicit labels only: supplier/vendor/seller, invoice number, invoice/purchase date in YYYY-MM-DD and grand/invoice total or amount due/payable. Amounts require an INR/Rs/rupee currency marker; foreign currency is not converted. Missing or conflicting values are flagged for manual entry. A total is not a per-asset valuation: Finance must check line items, quantity, tax and allocation before using it. Extraction accuracy is not guaranteed across invoice layouts or languages. Scanned/image-only PDFs do not have OCR and require manual entry. Legacy XLS, XLSM, encrypted files and automatic multi-asset allocation are unsupported.

The reviewer chooses each suggested field and acknowledges review before applying it to the form. Fields not chosen retain their current values. Applying suggestions is not approval. The ordinary independent reviewer, Finance-state and version checks still govern approval. A selected evidence ID and immutable hash are recorded in the approval event. An invoice can also be retained without using any suggestion.

Downloads require an authenticated Admin/Finance session, use attachment disposition, no-store cache headers and nosniff. Original documents can contain active content; open only trusted invoices in an updated viewer. This is not antivirus scanning or a malware-free certification. Do not upload real confidential invoices into a public demo. Bytes are in database backups, so operational retention, encryption, access review and deletion policy need IAC approval before production use. The current append-only record deliberately has no delete route; a legal erasure/retention design remains an operational gate.

Up to 50 distinct files can be retained per asset. Duplicate bytes do not create another file. Existing evidence is not deleted to make room; retention decisions need an approved administrative process. File IDs and hashes remain bound in approval history when used. Large-scale object storage, retention cleanup, OCR, broader date/layout support and automatic line-item matching are later work, not claims of this version.

## Verification

Synthetic PDF/XLSX extraction, ambiguity/foreign-currency handling, malformed/oversized/macro/archive safety, role restrictions, CSRF and If-Match, duplicate upload, private byte-for-byte download, immutable evidence, unchanged asset/state on upload and separate Finance approval are covered in automated tests. A disposable local dump/restore compares invoice rows including bytes and verifies restored append-only protection. These checks are not a production recovery or security certification.
